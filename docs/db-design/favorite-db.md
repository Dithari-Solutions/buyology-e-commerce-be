# Favorites — Database Design

## 1. Overview

The favorites feature lets authenticated users bookmark products they want to revisit later. The design is intentionally minimal: a single join table between `auth_credentials` and `products` with a composite unique constraint to prevent duplicates.

### Design decisions

- **One table only.** There are no "favorite lists" or "collections" in v1 — each user has a single flat favorites set. Adding lists later only requires a `favorite_lists` table and a new FK on this table.
- **Keyed on `auth_credential_id`, not `user_id`.** Every other feature (cart, orders) uses the credential as the session anchor, so favorites follows the same convention. This avoids a join back to `users` for every read.
- **Unique constraint, not soft delete.** Re-adding a product that was previously removed is a simple INSERT. There is no `removed_at` column — a row either exists (favorited) or does not (not favorited).
- **No `updated_at`.** Favorites are immutable once created. The only operations are insert and delete; `updated_at` would never change.

## 2. Entity-Relationship Diagram

```
auth_credentials
  │
```

`favorites` is a join table between `auth_credentials` and `products` with its own surrogate primary key and a timestamp.

---

## 3. Table Definition

### 3.1 `favorites`

```sql
CREATE TABLE favorites (
    id                  UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    auth_credential_id  UUID        NOT NULL REFERENCES auth_credentials(id) ON DELETE CASCADE,
    product_id          UUID        NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT uq_favorites_credential_product UNIQUE (auth_credential_id, product_id)
);
```

| Column               | Type        | Nullable | Notes                                               |
|----------------------|-------------|----------|-----------------------------------------------------|
| `id`                 | UUID        | NO       | Surrogate primary key, generated by the DB          |
| `auth_credential_id` | UUID        | NO       | FK → `auth_credentials.id`, cascades on delete      |
| `product_id`         | UUID        | NO       | FK → `products.id`, cascades on delete              |
| `created_at`         | TIMESTAMPTZ | NO       | Timestamp of when the product was favorited         |

---

## 4. Indexes

```sql
-- Primary lookup: all favorites for a given user
CREATE INDEX idx_favorites_auth_credential_id ON favorites (auth_credential_id);

-- Secondary lookup: count/list users who favorited a product
CREATE INDEX idx_favorites_product_id ON favorites (product_id);

-- The UNIQUE constraint already creates an index on (auth_credential_id, product_id)
-- which also satisfies the per-user lookup above — the explicit single-column index
-- on auth_credential_id is kept for cases where the planner prefers the narrower key.
```

---

## 5. Cascade Behavior

| Parent deleted            | Effect on `favorites`                             |
|---------------------------|---------------------------------------------------|
| `auth_credentials` row    | All favorites for that credential are deleted     |
| `products` row            | All favorites referencing that product are deleted|

Both cascades use `ON DELETE CASCADE`, which means no orphan cleanup is needed in application code. When a product is soft-deleted (`status = 'DELETED'`) the favorites row remains but the product will not be returned in active product queries. Hard deletion of a product automatically removes all favorites.

---

## 6. JPA Entity Mapping

The `Favorite` entity (`com.buyology.ecommerce.favorite.domain.Favorite`) maps this table directly:

- `authCredential` → `@ManyToOne(fetch = LAZY)` on `AuthCredentials`
- `product` → `@ManyToOne(fetch = LAZY)` on `Product`
- Both FK columns match the Hibernate convention (`auth_credential_id`, `product_id`)
- The unique constraint is declared via `@Table(uniqueConstraints = ...)` and enforced at the DB level

## 7. Sample Queries

```sql
-- All favorites for a user
SELECT f.id, f.product_id, p.sku, f.created_at
FROM favorites f
JOIN products p ON p.id = f.product_id
WHERE f.auth_credential_id = '<credential-uuid>'
ORDER BY f.created_at DESC;

-- Check if a product is favorited
SELECT EXISTS (
    SELECT 1 FROM favorites
    WHERE auth_credential_id = '<credential-uuid>'
      AND product_id = '<product-uuid>'
);

-- Admin: how many users have favorited a product
SELECT COUNT(*) FROM favorites WHERE product_id = '<product-uuid>';

-- Admin: full list with user email, paginated
SELECT f.id, f.auth_credential_id, ac.email, f.product_id, p.sku, f.created_at
FROM favorites f
JOIN auth_credentials ac ON ac.id = f.auth_credential_id
JOIN products p ON p.id = f.product_id
ORDER BY f.created_at DESC
LIMIT 20 OFFSET 0;
```
